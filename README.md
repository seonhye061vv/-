# 채용현황판

현업 담당자가 채용 공고별 진행 단계를 직접 확인하는 사내 채용현황판입니다. HR은 지금처럼 엑셀로 관리하고, 정해 둔 PC 폴더에 저장하면 현황판에 자동으로 반영됩니다.

## 구성

| 위치 | 내용 |
| --- | --- |
| `index.html`, `assets/` | 화면 (관리자·현업 공용, 로그인한 사람에 따라 다르게 보임) |
| `api/` | 서버 기능: 로그인, 공고 조회(권한 검사), 엑셀 받기·검증·반영, 권한 관리 |
| `lib/` | 엑셀 읽기 규칙(PRD 5절), 반영·권한 규칙 |
| `agent/` | 윈도우 PC 자동 동기화 프로그램 ([설치 방법](agent/README.md)) |
| `test/` | 시나리오 테스트 (`npm test`) |

## Vercel 설정 (처음 한 번)

1. **프로젝트 연결**: https://vercel.com/new 에서 이 저장소를 Import 하고 Deploy 합니다. Framework Preset은 Other 그대로 둡니다.
2. **데이터 저장소**: Vercel 프로젝트의 **Storage** 탭에서 **Upstash for Redis**(무료 요금제)를 만들어 이 프로젝트에 연결합니다. 연결하면 접속 정보가 환경 변수로 자동 등록됩니다.
3. **환경 변수**: Settings → Environment Variables 에 아래 세 개를 넣습니다.

   | 이름 | 값 |
   | --- | --- |
   | `ADMIN_PASSWORD` | HR 관리자 로그인 비밀번호 (12자 이상 권장) |
   | `TEST_ADMIN_PASSWORD` | (선택) 테스트용 관리자 `test_admin` 비밀번호. 넣지 않으면 test_admin 로그인은 막힘 |
   | `SESSION_SECRET` | 32자 이상 아무 문자열 (로그인 정보 서명용, 공유하지 않음) |
   | `SYNC_KEY` | 32자 이상 아무 문자열 (PC 동기화 프로그램 인증용) |

4. 환경 변수를 넣은 뒤 **Deployments → Redeploy** 를 한 번 눌러 반영합니다. (main 브랜치에 새 커밋을 올려도 자동으로 다시 배포됩니다.)
5. 배포 주소(프로젝트 기본 도메인)에서 로그인 이메일 `admin`, 비밀번호 `ADMIN_PASSWORD` 값으로 들어가면 관리자 화면(열람 권한 탭 등)이 열립니다.

## 사용

- **HR 관리자**: 아이디 `admin`, 비밀번호는 `ADMIN_PASSWORD` 값.
- **테스트 관리자**: 아이디 `test_admin`, 비밀번호는 `TEST_ADMIN_PASSWORD` 값(설정했을 때만). 권한은 관리자와 같습니다. 테스트가 끝나면 환경 변수를 지우고 재배포하면 바로 막힙니다.
  - 엑셀 반영: 직접 올리기 (검증 결과 확인 후 반영)
  - 열람 권한: 권한부여대상자 시트의 대상자(이름)마다 로그인 이메일을 연결하면 임시 비밀번호가 자동 발급되어 한 번만 표시되고(잊으면 재발급), 공고마다 드롭다운에서 대상자를 골라 승인·회수
  - 권한부여대상자 명단만 따로 올리기: 본부·부서·권한부여대상자N·이메일주소 열 순서의 엑셀. 명단의 이메일이 로그인 이메일 칸에 미리 채워짐. 백데이터 엑셀에 '권한부여대상자' 시트가 있으면 반영할 때마다 그 시트로 명단이 바뀌고, 없으면 마지막으로 올린 명단을 유지
  - 현황판: '완료 공고 표시'에서 모든 단계가 끝난 공고를 완료 후 며칠까지 보여 줄지 설정 (기본: 완료 후 7일까지, 그 뒤 현업 화면에서 숨김)
  - PC 자동 동기화: 확인 주기 설정, 연결 상태 확인
  - 현업 화면 보기: 권한부여대상자를 골라 그 사람이 보는 화면을 그대로 확인 (계정 연결 전에도 가능, 보기 전용)
- **현업 담당자**: HR에게 받은 이메일과 임시 비밀번호로 처음 로그인하면 비밀번호를 새로 정해야 하고, 그 뒤 승인된 공고만 보입니다. 다른 공고는 주소를 직접 입력해도 서버가 막습니다.

## 데이터와 보안

- 채용 데이터는 Vercel에 연결한 Upstash Redis에만 저장됩니다. 이 저장소(GitHub)에는 실제 데이터를 올리지 않습니다.
- 비밀번호는 암호화(해시)해 저장하고, 비밀 값은 모두 Vercel 환경 변수로 관리합니다.
- 회사 데이터 보관 기준상 외부 클라우드 사용이 가능한지 확인한 뒤 실제 데이터를 넣어 주세요.

## 로컬에서 확인

```
npm install
npm run dev     # http://localhost:3000 , 관리자 비밀번호 admin, 데이터는 메모리에만 저장
npm test        # PRD 10절 시나리오 테스트
```

## 사용 편의 기능 (2026-10-14)
- 열람 권한 탭 '한 번에 처리하기': 명단 이메일로 모두 연결, 같은 본부·부서 후보 모두 승인. 공고마다 '후보 모두 승인' 버튼도 있음.
- 이번에 발급한 임시 비밀번호는 '엑셀로 내려받기'로 한 파일에 받음(서버에는 저장하지 않음).
- 현황판 표는 9단계를 진행 막대 한 칸으로 보여 주고(마우스를 올리면 단계 이름), 'N/9단계 처리'로 진행률 표시.
- '현재 단계별 공고 수' 막대를 누르면 그 단계 공고만 보임.
- 로그인: 비밀번호 보기, 이 브라우저에서 이메일 기억하기, 비밀번호 분실 안내.
- 열람 권한 탭 '대상자 직접 추가': 명단에 없는 사람을 이름·이메일·소속으로 추가(바로 연결 가능). 명단 파일을 다시 올려도 유지되고, 직접 추가한 사람만 삭제 가능.
- 공고별 HR 메모: 공고 상세 창에서 관리자가 작성(300자), 현황판 공고명 아래와 현업 화면에 함께 보임.
- 채용 통계 탭: 요약(전체·진행 중·완료·평균 진행률), 단계별 평균 소요일, 지금 단계에 오래 머문 공고, 부서별 현황, 월별 완료. '보고용 엑셀 내려받기'(recruit-stats_날짜.xlsx). 소요일은 시스템 등록 이후 엑셀 반영 기록 기준.
